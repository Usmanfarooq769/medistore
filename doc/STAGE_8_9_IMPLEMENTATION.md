# MediStore Stage 8 and Stage 9

This patch extends the existing Laravel 12 / Vue 3 application. It does not replace the existing Stage 1–7 modules.

## Stage 8 — Ecosystem expansion

### Customer self-service portal

Customer accounts are activated using a one-time invitation generated by an administrator. The invitation expires after 24 hours and is stored hashed. The customer sets a password (minimum 10 characters), then signs in with their registered customer phone number and password. Customer portal bearer tokens are stored hashed and expire after 30 days.

Routes:

- `POST /api/enterprise/customers/{customer}/portal-invitation` (admin)
- `POST /api/customer-portal/redeem-invitation`
- `POST /api/customer-portal/login`
- `GET /api/customer-portal/dashboard`
- `GET /api/customer-portal/orders`
- `GET /api/customer-portal/invoices`
- `POST /api/customer-portal/orders`
- `POST /api/customer-portal/logout`

The invitation token must be delivered to the customer through a separately verified channel. Do not post it publicly or send it to an unverified phone number. Customer orders are requests only; inventory is not reserved or deducted until pharmacy staff process the POS sale.

### Partner API and webhooks

An administrator creates a partner API client and assigns scopes. The raw client secret is shown once. Partner requests send `X-Partner-Key` and `X-Partner-Secret` headers. Secrets are stored as password hashes. Partner requests are rate-limited and logged.

Available scopes and routes:

- `catalog:read` — `GET /api/partner/v1/catalog?branch_id=1`
- `orders:write` — `POST /api/partner/v1/orders`

Webhook endpoints must use HTTPS. Supported order events include `order.created`, `order.confirmed`, `order.cancelled` and `order.sale_linked`. Payloads are HMAC-SHA256 signed in `X-MediStore-Signature`. Failed deliveries retry with backoff up to five attempts. Configure outbound network egress restrictions at the server/firewall level as an additional SSRF safeguard.

Commands:

```bash
php artisan partners:deliver-webhooks
```

### Branch subscriptions

Subscription plans, branch subscriptions, invoices and administrative payment records are included. The payment-record endpoint is a manual accounting/admin record; it does not contact a bank or payment gateway. Verify funds with your payment provider before marking an invoice paid. Seeded plan prices are zero placeholders and must be configured by the business before commercial use.

### Notifications and PWA

The authenticated notification center supports per-user read state and administrator announcements. The service worker can display incoming browser push events and handle notification clicks. A push provider/VAPID sender must be configured separately to deliver actual push messages. Authenticated API responses are never cached by the service worker.

Customer portal UI: `/customer-portal`.
Admin enterprise UI: `/enterprise-platform`.

The mobile workflow in this release is the existing installable PWA, not a compiled native Android APK or iOS application. Native apps and direct integrations with specific payer/hospital vendors remain future work and require their API specifications, credentials and acceptance testing.

## Stage 9 — Production readiness

Admin UI: `/system-readiness`.

Routes under `/api/system-readiness` provide non-destructive checks for database, cache, storage write access, failed jobs, recent backup status and basic application configuration. Snapshots are persisted. Deployment releases and disaster-recovery drills are registers; they do not deploy files or perform a database restore.

Command:

```bash
php artisan system:health-check
```

The scheduler runs health checks hourly and partner webhook delivery every minute. The existing Laravel scheduler cron must be active.

A successful health snapshot is not a penetration test, regulatory certification, load test or proof that a backup can be restored. Conduct independent security review, load tests, and a full restore drill in an isolated staging environment before production launch.

## Installation

Back up the project and database. Extract this patch into the existing project root, then run:

```bash
php artisan migrate
php artisan db:seed --class=StageEightNineReferenceSeeder
php artisan optimize:clear
npm run build
```

For a roadmap-only refresh (including marking Stage 7 complete based on the owner's confirmation):

```bash
php artisan db:seed --class=StageEightNineRoadmapSeeder
```

The seeders are safe to rerun: they create missing plan and roadmap reference records and do not create sales, purchases, stock movements, payments or other operational transactions.

## Configuration preservation

No `.env`, Composer files, npm lock files, WhatsApp credentials, mail credentials or storage credentials are included in this patch. No new Composer or npm dependency is required.
